# I18N — Internationalization

Lightweight React-context i18n for the KriyaDot web console. Deliberately
small: no next-intl server features, no middleware, no async locale chunks —
pure React context + `localStorage`, so it works identically in `next dev`,
the **static export** (`next build` → `apps/desktop` Tauri shell), and unit
tests.

- Infra: `apps/web/lib/i18n.tsx` (`I18nProvider`, `useI18n()`, `LanguageSwitcher`)
- Dictionaries: `apps/web/lib/locales.ts` (`en` = source of truth; 15 locales total: `en`, `hi`, `ru`, `it`, `pl`, `ja`, `ptBR` — the `pt-BR` dictionary — plus `de`, `es`, `fr`, `tr`, `uk`, `vi`, `zh`, `zh-TW`)
- Persistence: `localStorage` key `mvp:locale` (any shipped locale id, default `'en'`)
- `<html lang>` is synced on every language change.

## Using strings in a component

```tsx
import { useI18n } from '../lib/i18n';

function MyPanel() {
  const { t, locale, setLocale } = useI18n();
  return <h1>{t('bots.title')}</h1>;                       // "Bots" / "बॉट्स"
  return <p>{t('chat.composerPlaceholder', { bot: 'Aria' })}</p>; // {var} fill
}
```

`t(key, vars?)` looks the dot-path up in the active locale, falls back to
English, then to the key itself (never crashes, never renders `undefined`).
Outside an `I18nProvider` it falls back to English so components still render
in isolation and in tests.

## Adding strings

1. Add the key to `en` in `apps/web/lib/locales.ts` first (English is the
   source of truth; `export type Strings = typeof en` enforces the shape).
2. Mirror the key in every other locale (`hi`, …) with the translation.
3. Use it via `t('path.to.key')` / `t('path.to.key', { name })`.
4. `lib/i18n.test.ts` asserts every locale has exactly the `en` key set —
   CI catches a missing translation.

Keep values UI-facing only (no secrets, no PII). Prefer sentence-case
matching the existing English chrome.

## Adding a locale

1. In `apps/web/lib/locales.ts`, add `export const xx: Strings = { … }`
   (copy the `en` object; TypeScript errors on any missing/mistyped key).
2. In `apps/web/lib/i18n.tsx`:
   - extend `LocaleId` (`'en' | 'hi' | 'xx'`),
   - add `{ id: 'xx', label: '…', englishLabel: '…' }` to `LOCALES`,
   - add the id to `VALID` and the dict to `DICTS`.
3. Add a translation smoke assertion to `lib/i18n.test.ts` if you want one
   (the completeness check is automatic).
4. No build config changes needed — dictionaries are bundled statically.

## Voice roadmap (for the next workstream)

- `CallPanel`'s `respond` is a mock brain in the MVP. For a real bot turn,
  collect `streamChat({ botId, message: transcript, sessionId })` tokens into
  text and return it — the STT→respond→TTS pipeline (`lib/voice-call.ts`
  `runCallTurn`) needs no changes.
- Voice providers: `lib/voice-http.ts` implements the `@mvp/voice`
  `STTProvider`/`TTSProvider` interfaces over the API's `/api/voice/*`
  routes (mock-backed). Point the API at real providers via
  `VOICE_STT_PROVIDER`/`VOICE_TTS_PROVIDER` and the web UI picks them up
  with zero client changes.
