# KriyaDot Benchmarks

Two benchmark families, measuring different things:

1. **Harness micro-benchmarks** — how fast KriyaDot's deterministic
   plumbing is (embedder, memory recall, session storage, discovery,
   supervisor gate). No model quality is involved.
2. **Task suite** — defined tasks with deterministic, auto-scored
   outcomes, run against a provider. This is the "real task
   benchmark": tasks, scorers, and published results.

Latest runs: 2026-10-30 (IST) on Node v24.22.1, linux/x64, one shared
machine — absolute numbers vary by hardware; rerun to reproduce.

## 1. Harness micro-benchmarks

Generated by `packages/agent-runtime/benchmarks/run.mjs`
(run 2026-10-29T19:34:39Z). These are **local micro-benchmarks of
deterministic harness components**: the offline embedder, memory

## 2. Task suite (auto-scored)

Defined in `packages/agent-runtime/benchmarks/tasks/tasks.mjs`,
executed by `packages/agent-runtime/benchmarks/tasks/run-tasks.mjs`.
Eight tasks in four categories; every scorer is **deterministic** —
no model grades anything:

- **fix-the-bug** (2 tasks): the returned function is executed in a
  `node:vm` sandbox and checked against assertions (partial credit =
  assertions passed / total).
- **extract-values** (2 tasks): the reply is JSON-parsed and compared
  field-by-field, exactly.
- **follow-instructions** (2 tasks): format constraints checked
  mechanically (exact JSON-only reply; exactly 3 bullet lines).
- **tool-use** (2 tasks): scored on the exact tool calls returned —
  right tool with right args = 1; unnecessary tool call or a
  destructive unrequested call = 0.

A task passes at score >= 0.99. Scorer discrimination is verified:
fed the *original buggy* cart function, the fix-the-bug scorer
returns 0.5 (2 of 4 assertions fail), and a `delete_file` call on the
read task returns 0.

> **What this does and does not claim.** In mock mode the runner

> **not** evidence about any real model's ability, and must never be
> quoted as a model score. Machine-readable results:
> `packages/agent-runtime/benchmarks/tasks/results/task-results.json`
> (+ `task-results.md`).

### Running the suite against a real model

```sh
cd packages/agent-runtime
npm run build
BENCH_PROVIDER=groq BENCH_MODEL=gpt-oss-120b GROQ_API_KEY=... \
  node benchmarks/tasks/run-tasks.mjs --write
```

`BENCH_PROVIDER` accepts any provider id from
`packages/agent-runtime/src/providers/catalog.json`; `BENCH_MODEL`
is optional (defaults to the provider's default model). The runner
refuses to start when the provider's key env var is missing (exit 2 —
no key, no network call). Real-provider runs write the same results
files with the real provider/model named in them; check the
`provider` field before quoting any number.
